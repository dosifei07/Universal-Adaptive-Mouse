## 1. Purpose

Determine whether changing pointer sensitivity by movement direction and by
movement speed improves 2D pointing performance, and whether it does so
without unacceptable regressions elsewhere.

This protocol exists so that the metrics, comparisons, exclusion rules, stopping
rules and the definition of "no effect" are fixed **before** data is seen. A
negative result is an acceptable and fully reportable outcome.

### Scope and non-claims

- The task is a 2D pointer task on a flat canvas. A result here does **not**
  establish an effect in first-person aiming, and it says nothing about 3D
  sensitivity, field of view or engine acceleration.
- The gains studied come from the current prototype math (README, "How the v0.1
  model works"). Those constants are engineering defaults. This study tests
  them; it does not assume they are correct.
- No operating-system hooks, drivers or game integrations are involved.

## 2. Research questions and hypotheses

| # | Research question | Hypothesis (directional, to be tested against the null) |
| --- | --- | --- |
| RQ1 | Are directional weaknesses consistent across sessions? | H1: per-sector signed bias is stable across sessions (criteria in 8.1). |
| RQ2 | Can systematic error be separated from random error? | H2: between-session variance of sector bias is smaller than within-session trial variance for at least some sectors (8.2). |
| RQ3 | Do fast flicks and slow corrections need different adjustments? | H3: bias differs between the slowest and fastest speed bands within participants (8.3). |
| RQ4 | Does improving one direction cause regressions elsewhere? | H4: the number and size of per-sector regressions are within the limits in 9.3. |
| RQ5 | What is the minimum evidence required before a change is proposed? | Estimated, not tested: see section 10. |
| RQ6 | What are the input latency and movement consistency of the capture? | Measured in the capture validation sub-study (section 11), which gates everything else. |

Primary confirmatory hypothesis (the only one with a confirmatory claim):

> **HP:** Hybrid adjustment (condition D) changes effective throughput relative to
> the original sensitivity (condition A) by at least the smallest effect of
> interest (section 9.1).

All other comparisons are secondary or exploratory and are labelled as such in
the report.

## 3. Design

Within-subject, repeated-measures, randomized and counterbalanced.

### 3.1 Conditions

| Code | Behavior | Role |
| --- | --- | --- |
| A | Original sensitivity (baseline) | Reference |
| B | Directional gains only | Test |
| C | Speed gains only | Test |
| D | Directional and speed gains combined | Test (primary) |
| A′ | Original sensitivity, last block of every session | Drift check: learning and fatigue |
| N | Sign-reversed D gains, same magnitude | Negative control (section 3.5) |

### 3.2 Phases

1. **Instrument check** (section 3.5), once per participant.
2. **Calibration phase:** 2 sessions on separate days, condition A only. These
   sessions are the **only** data used to fit the player model and compute the
   gains used in B, C, D and N.
3. **Frozen gains:** gains are computed once from calibration data by the
   unmodified `OptimizationEngine`, serialized, hashed and stored in the session
   metadata. They are **not updated** during the study. Online or adaptive
   updating is out of scope (that is v0.9).
4. **Experimental phase:** 4 sessions on separate days (**[DECISION]** minimum
   gap, proposed: at least one calendar day between sessions, none more than
   seven apart).

### 3.3 Session structure (experimental phase)

Each session has five scored blocks plus a warm-up:

```text
warm-up (A, unscored)  →  block 1  →  block 2  →  block 3  →  block 4  →  A′
```

Blocks 1 to 4 contain conditions A, B, C and D, one each. Condition N replaces
one block in one of the four sessions (assigned by the seeded randomization in
3.4) so that every participant experiences it once.
**[DECISION]** whether N is run for every participant or only in a subset.

Proposed block size: 96 trials = 8 direction sectors × 3 distances × 4
repetitions. Proposed breaks: at least 60 seconds between blocks, no block
longer than **[DECISION]** minutes.

### 3.4 Randomization and counterbalancing

- Block order within a session follows a balanced (Williams) Latin square for
  four conditions:

  ```text
  Row 1: A B D C
  Row 2: B C A D
  Row 3: C D B A
  Row 4: D A C B
  ```

- Each participant receives all four rows, one per session, in an order
  determined by a seeded shuffle of the rows.
- The random seed, the resulting row order and the per-trial target sequence
  are stored in the session metadata so that a session can be regenerated
  exactly (consistent with invariant 7 in `architecture.md`).
- Target direction, distance and repetition order within a block are seeded and
  balanced so each sector × distance cell has equal counts.
- Participants are **blind to condition**. The UI shows no condition label,
  gain values or recommendation during experimental sessions.

### 3.5 Instrument check and controls

The study can only report "no effect" credibly if the measurement could have
detected an effect. Two checks:

- **Instrument check (once per participant, before calibration):** one block
  with a uniform global gain of 0.90 and one with 1.10, which should shift the
  mean signed error ratio in the predictable direction. If the instrument does
  not detect an effect of that size, collection stops and the capture is fixed
  (section 11).
- **Negative control (condition N):** if reversed-sign gains do not worsen
  performance relative to A, the measure is not sensitive enough to support any
  "no effect" conclusion for B, C or D.

## 5. Apparatus and conditions of capture

Recorded per session in the document metadata (this requires the schema bump
in section 14):

- mouse model, DPI, polling rate, sensor type if known
- display resolution and refresh rate, canvas size in physical pixels
- surface and mouse-pad type
- OS and version, Lab application version and commit hash
- OS pointer acceleration state ("Enhance pointer precision" on Windows or the
  equivalent): **must be off**, and sessions where it is on are excluded
- participant handedness and grip style (self-reported)

Gain application:

- **Applied from the input stream only.** Directional gain is selected from the
  instantaneous direction of motion computed from the input deltas, **not** from
  the known target position. A real input layer (v0.5) cannot know the target,
  so using it here would overstate what is achievable.
- Gains are applied to relative deltas before the cursor is drawn.
- The experimental profile is Lab-scoped: it cannot be exported, cannot be
  converted into a `GameProfile` and bypasses `RecommendationApprover` only
  inside UAM Lab, with explicit per-session participant consent. An
  `ArchitectureTests` check enforces this boundary.

## 6. Task definition

- A trial starts when the participant clicks a start marker. A target appears at
  a seeded direction and distance (3 distances, **[DECISION]** pixel values) and
  a diameter chosen to give a target index of difficulty between **[DECISION]**
  bits.
- A trial ends on click. A hit is a click inside the target.
- Recorded per trial: start and end position, target position and size,
  movement time, full trajectory with timestamps, endpoint, signed error ratio
  (positive overshoot, negative undershoot), peak and mean speed, hit flag,
  condition code, applied gains, and block and trial index.
- Trials follow the existing `TrainingObservation` contract and pass through
  `ObservationValidator`. Observations rejected by the validator are reported
  and excluded from every analysis.

## 7. Metrics

### 7.1 Primary metric (fixed now)

**Effective throughput (TP_e), ISO 9241-9 style,** per participant per condition,
computed from block-level data: effective index of difficulty from the effective
target width (from endpoint spread) divided by mean movement time.

Throughput is primary because it accounts for the speed-accuracy tradeoff; a
condition that is faster but less accurate does not automatically win.

If the capture cannot supply the endpoint and timing data this needs, the
protocol is amended before data collection (not after).

### 7.2 Secondary metrics

- mean movement time
- hit rate
- mean absolute signed error ratio
- per-sector signed bias and per-sector variance
- overshoot and undershoot rates
- path efficiency (path length divided by straight-line distance)
- correction count (sub-movements)

### 7.3 Diagnostics (never used for inference)

- block order and session effects
- A versus A′ difference (drift)
- per-trial capture timing (section 11)
- participant-reported fatigue **[DECISION]** (single 1–7 item after each block)

## 8. Analysis of the research questions

### 8.1 Directional consistency (RQ1)

For each participant and each of the 8 sectors, compute the mean signed error
ratio per session using condition A trials only (including A′).

A sector bias is **stable** if all of the following hold:
- the sign is the same in at least **[DECISION: 3 of 4]** experimental sessions
  plus both calibration sessions,
- the intraclass correlation (ICC) of sector bias across sessions is at least
  **[DECISION: 0.5]**,
- the bootstrap 95% interval of the mean across sessions excludes zero.

If no participant has a stable bias in any sector, H1 is rejected and the
corrective premise of the directional model is unsupported.

### 8.2 Systematic versus random error (RQ2)

Fit a mixed-effects model of signed error ratio with sector and condition-A
status as fixed effects and random intercepts for participant, session and
participant × sector. Systematic error is the participant × sector component;
random error is the residual. Report the variance components and their ratio.
A bias counts as correctable only if the systematic component is meaningfully
larger than the residual, with the threshold **[DECISION]** fixed here.

### 8.3 Speed dependence (RQ3)

Speed bands are the three global defaults in the current code, **and** a
sensitivity analysis uses per-participant tertiles computed from calibration
data only. If the two give different conclusions, both are reported and the
global bands are flagged as a limitation.

### 8.4 Regressions elsewhere (RQ4)

See section 9.3.

## 9. Outcomes and decision rules

### 9.1 Smallest effect of interest

A change in effective throughput of **[DECISION: proposed 3%]** relative to A
is the smallest effect worth acting on. Anything smaller is treated as no
practically relevant effect.

### 9.2 Primary comparison

D versus A on effective throughput, per participant and overall, using a linear
mixed-effects model with condition as a fixed effect, random intercepts for
participant and session, and block order and trial index (block-centered) as
covariates. Report the effect size, a 95% confidence interval, and the
participant-level distribution (not only the mean).

The warm-up trials and the **first 16 trials of every scored block** are
excluded from the primary analysis to let participants adapt to a changed
sensitivity. They are still recorded and reported.

### 9.3 Regression criterion

A sector **regresses** if its mean absolute signed error ratio under the
adjusted condition is worse than under A by more than **[DECISION: proposed 5%]**
and the 95% interval of the difference excludes zero after correction.

The result is **unacceptable** if any of these holds:
- more than **[DECISION: 1]** of 8 sectors regresses,
- any single sector regresses by more than **[DECISION: 10%]**,
- hit rate falls by more than **[DECISION: 2 percentage points]** overall.

### 9.4 Multiple comparisons

- Confirmatory: only D versus A on the primary metric. No correction.
- Secondary: B versus A, C versus A, D versus B, D versus C, and all secondary
  metrics are reported with Holm correction within each family.
- Everything else is exploratory and labelled as such.

### 9.5 Possible conclusions

| Outcome | Definition | Consequence |
| --- | --- | --- |
| **Positive** | D improves throughput by at least the smallest effect of interest, the interval excludes zero, no unacceptable regression (9.3), instrument and negative controls behave as expected | Evidence that the model helps in this task. Carry to v0.5 sandbox design with the stated limits. |
| **Negative** | Equivalence shown: the 90% interval for D − A lies entirely within ±**[DECISION: smallest effect of interest]** (two one-sided tests), controls behave as expected | Clear negative result. Revise the hypothesis; do not proceed to input integration on this model. |
| **Harmful** | Unacceptable regression, or N and D differ in the opposite direction than expected | Stop; the model is not safe to deploy in its current form. |
| **Inconclusive** | Interval spans both the smallest effect of interest and zero, or a control failed | Report as inconclusive. Do not describe it as "no effect". Decide on a follow-up with a revised, newly registered protocol. |

## 10. Minimum evidence before a change is proposed (RQ5)

This is estimated from the data, not assumed. The study will report, per
sector and speed band:

- the number of trials after which the estimated bias is within
  **[DECISION: ±1%]** of its eventual calibration-phase value in at least 90% of
  resamples,
- the number of sessions on separate days needed for stability (8.1),
- how that compares with the current gate (confidence `n / (n + 30)` with
  `n ≥ 10` per bucket and confidence ≥ 20%).

The output is a recommended revision of the gate, if the data supports one. It
does not change the gate during the study.

## 11. Capture validation sub-study (RQ6)

This runs first, on the intended hardware, and gates all later steps.

**Measures**
- distribution of inter-event intervals versus the device's nominal polling rate
- dropped or merged events, and event-timestamp jitter
- end-to-end latency from input to rendered cursor, using the best available
  method (**[DECISION]**: external high-speed camera, hardware latency tester, or
  an in-software estimate with its limitations stated)
- movement consistency: repeated identical synthetic or replayed paths should
  produce trajectories that differ by less than the effects of interest

**Gate (all must pass, thresholds [DECISION])**
- median inter-event interval within ±**[x]**% of nominal
- fewer than **[y]**% dropped events
- timing jitter 95th percentile below **[z]** ms
- latency known and constant across conditions (gain application adds no
  condition-dependent delay)

If any criterion fails, the capture is fixed or the effect sizes the study can
detect are restated before proceeding.

## 12. Stopping rules

- **Fixed schedule:** data collection ends after the planned participants have
  completed all sessions, or on **[DECISION: date]**, whichever is first.
- **No interim efficacy looks.** No result for the primary comparison is
  computed before collection ends. Interim checks are limited to data quality
  and safety.
- **Individual stopping:** a participant's adjusted conditions stop if (a) they
  withdraw, (b) they report pain or discomfort, or (c) a Lab-scoped safety check
  finds a hit-rate drop of more than **[DECISION: 15 percentage points]** versus
  A in two consecutive adjusted blocks. Their remaining sessions continue under
  A only if they agree.
- **Futility is not a stopping rule.** The study runs to completion even when
  early trends look null, so that the negative outcome is well-powered.
- A change to the plan is an amendment (section 16), never a silent edit.

## 13. Data exclusion and quality rules

Fixed before data collection:

- **Trial level:** rejected by `ObservationValidator`; movement time below
  **[DECISION]** ms or above **[DECISION]** s; accidental clicks identified by
  the Lab (click before any movement); capture gaps.
- **Block level:** more than **[DECISION: 10]**% trials excluded; a recorded OS or
  hardware change mid-session; a timing-gate failure (section 11).
- **Session level:** pointer acceleration on; a session interrupted for more
  than **[DECISION]** minutes; participant-reported illness or injury.
- **Participant level:** fewer than **[DECISION: 3 of 4]** valid experimental
  sessions, or a failed instrument check.
- All exclusions are counted and reported by reason and condition. A result is
  always shown both with and without the exclusions.
- Excluded data is kept (marked, not deleted), consistent with the existing
  rule that invalid observations are not used for modeling.

## 15. Analysis plan and reporting

- Analysis code is written and committed against synthetic data (including data
  generated with known effect sizes and with zero effect) before any real data
  is collected, and is run unchanged afterward.
- All analyses run from stored raw data; no hand-edited intermediate files.
- Report: every pre-registered analysis, every deviation, effect sizes with
  intervals, per-participant plots (not only averages), the instrument and
  negative control results, exclusions, and the capture validation results.
- Exploratory analyses are reported in a separate section and called
  exploratory.
- Results are reported whether positive, negative, harmful or inconclusive.
- The raw data and analysis code are retained so the analysis can be reproduced.

## 17. Limitations (known in advance)

- 2D pointer task on a flat canvas. No claim about first-person camera aiming,
  3D sensitivity, field of view or engine acceleration.
- A small number of participants limits generalization; an N-of-1 study
  supports individual conclusions only.
- Gain constants and speed bands come from the v0.1 prototype and are not
  physiologically validated.
- Confidence in the current engine uses sample count only.
- Participants know they are in a study (Hawthorne effect) and may adapt
  strategies across sessions.
- Gains are frozen, so this study cannot say anything about adaptive or
  continuously updating adjustment (v0.9).
- Results depend on the specific mouse, DPI and surface used.
